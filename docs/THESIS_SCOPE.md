# 新课题范围与路线：复杂场景下的海上民用船舶识别

本文件定义新课题的命题、数据能力边界、闸门与预算。它是**前置准备**，不是实验结果；
所有数字来自本项目已完成的运行与已确认标签，引用处给出工件名。

## 1. 题目与标签空间（已定：做"类型"）

课题启动时给的题目写作"民用船舶**型号**识别"，用户已确认**做到"类型"即可**，不追求建造型号/船只 ID。
因此全文统一写"船型/类别识别"（英文：civilian ship *type* recognition）。

依据：

- FGSC-23 的类别是**船型/用途**（container ship、oil tanker、bulk carrier、fishing boat 等），
  `docs/DATA_PROTOCOL.md` 已写明"标签名称表示船型，不代表建造型号或船只 ID"。
- FGSRCS 是 17 类（以军舰为主），民用相关裁剪 862 个，严格可映射到 FGSC-23 的只有两类。
- 公开数据中未发现"民用船型 × 逐图真实退化"的数据集（`docs/SOTA_LANDSCAPE.md` 数据节），
  所以类型级评测只能靠本项目人工标签 + 合成退化。

## 1.1 启动指标映射（课题启动要求 → 可验收项）

启动时给的要求是流程性的（"搜集 SOTA → 退化处理 → 观察退化 → 做模块 → 对比提升 → 真实数据验证"），
没有给数值指标。为避免最后无法验收，下表把它逐条转成可检查的交付与门槛。**数字为本项目提议，
需与导师确认；确认后不得在看到结果后修改。**

| # | 启动要求 | 交付物 | 验收口径（提议） |
|---|---|---|---|
| R1 | 搜集 SOTA 民用船舶识别模型 | `docs/SOTA_LANDSCAPE.md` + 复现运行 | ≥3 个有公开代码的模型；干净条件相对论文口径差距 ≤2 pp，否则标"架构复现" |
| R2 | 对数据集做退化处理（浓雾、眩光、碎云） | 条件集 + 生成脚本 | 三类退化各 ≥3 强度；合成按构造保留标签；学习式生成须逐图审查 |
| R3 | 观察并保留退化现象 | 43+ 条件逐样本概率与曲线 | 条件可复现（固定种子）、逐样本可重算、报告不手填数字 |
| R4 | 针对退化做模型/模块 | 模块代码 + 三骨干三种子运行 | 见 G2 准入（退化层 ≥+1.0 pp、≥2/3 种子为正、干净 ≥−1.0 pp） |
| R5 | 与保留的 SOTA 对比并提升仿真性能 | 配对比较表 | 同数据同配方；增益必须给出种子范围与组 bootstrap CI |
| R6 | 实际退化数据做消融验证 | 真实分层 + 消融表 | ≥1 个真实退化数据源；标签人工确认；负结果也报告 |
| R7 | 性能与成本 | 参数量/FLOPs/延迟表 | 每百分点增益的成本增量；简化版须保持 ≥ 原增益的一半 |

## 2. 动机必须建立在正确的退化事实之上

已完成的真实退化分层评测（`reports/REAL_DEGRADATION_STRATIFIED.md`，157 + 184 张人工确认标签）
给出的边界：

| 事实 | 数值 | 对课题的含义 |
|---|---|---|
| FGSC-23 val 任一真实退化 | accuracy Δ −2.3 pp（种子 −7.8 至 +4.3，CI 跨零） | 不能声称"真实退化导致准确率大幅下降" |
| 雾/霾层 | accuracy −4.3 pp，但 balanced accuracy 86.6 → 73.1 | 退化主要改变**错误结构/类别偏向**，不是整体失效 |
| 场景杂乱 | −11.5 pp（−16.3 至 −1.5，CI 不跨零） | 当前唯一稳定的负向因子，属场景因素 |
| FGSRCS 清晰层 | accuracy 约 76.3 | 跨库域差大于退化差异 |
| 厚云 / 重度 | FGSC-23 0 / 2 张，FGSRCS 4 / 2 张 | 无法支撑"厚云、重度"结论 |

结论：论文动机只能写成"**严重合成退化（4–5 级）与跨库域差下性能显著下降**"，并明确合成退化是
受控仿真，不能外推为真实天气结论。写成"真实复杂场景下退化导致大幅掉点"会被自己的数据反驳。

## 3. 与已停止模块线的关系（必须换掉的三件事）

新路线在步骤上与原模块线重合（基线 → 退化观测 → 模块 → 对比 → 真实验证）。原路线已用 6 类候选
全部失败并停止（`reports/ROUND2_DECISION.md`）。新课题要成立，必须至少换掉以下三点，否则是可预期的重演：

1. **基线换成外部 SOTA**：原准入基线是自家组合增强的 ResNet-50 / Swin-T / ConvNeXt-T。
   新课题以文献可比的 SOTA 为参照，性能天花板与说服力都不同。
2. **目标从"均值 macro-F1 打赢"改为"严重退化层保持率 + 最差条件 + 成本"**：
   均值口径已经被证明对 4–5 级退化不敏感的方向（干净掉点抵消退化增益）。
3. **真实验证改写为"接受并披露负结果"**：真实验证不再作为"证明提升"的环节，而作为
   边界检验——若合成增益不迁移，如实报告，这正是已有 −2.3 pp 事实的延续。

## 4. 已证伪方向（不要重试，除非给出不同机制）

| 方向 | 结果 | 工件 |
|---|---|---|
| 零训练光度复原（CLAHE、饱和填充、概率融合） | 干净掉 3.4–3.8 pp；净收益不稳 | `reports/ROUTE_AB_ROUND1.md` |
| 配对监督复原网络（0.8M U-Net） | PSNR 6.3→17.3 dB，Macro-F1 −8.6 / −10.6 / −7.0 | `reports/PAIRED_RESTORER_ROUND1.md` |
| 联合训练一致性 C2 / C3 | 均值 −1.5 / −0.8 至 +1.1，无稳定增益 | `reports/JOINT_ROUND1.md` |
| token 重加权（RGPA） | 未通过准入；7×7 重加权处理不了 token 内部毁伤 | `reports/RGPA_ROUND1.md` |
| 生成式数据增强（GenDeg） | 高 μ 下 16 个样本中 3 个结构失效；标签有效性须逐图审查 | `docs/LITERATURE.md` |
| 由图像统计自动判定退化标签 | 禁止；必须人工确认 | `docs/DATA_PROTOCOL.md:37` |

共同机制：**像素/特征层面的"恢复"不等于"判别保留"**。新模块若仍以重建或一致性为目标，
需要先解释它为什么不受此机制约束。

## 5. 可直接复用的资产（前置准备的主要价值）

- 退火/评测协议：43 条件（matched/shifted × haze/cloud/glare × 1–5 级 + 组合 + 位置对照），
  逐样本概率落盘，`src/maritime_robust/degradations.py`。
- 冻结分类器：7 个（ConvNeXt-T/Swin-T 各 3 种子、ResNet-50 s17），`runs/`，共 45 个基线运行。
- 23 类本地基线：`runs/fgsc23_research_all/`（clean / aug / combo × 3 模型 × 3 种子）。
- 真实退化标签：`reviews/real_degradation/`（157 + 184 张，人工确认，含 SHA）。
- 工具链：`merge_degradation_labels.py` → `real_degradation_predict.py` → `real_degradation_eval.py`
  → `real_degradation_report.py`；`audit_delivery.py` 负责工件验收。
- 准入规则（原样沿用）：同数据、同种子、配对、干净不降、至少 2/3 种子为正。

## 6. 四道闸门（新课题的预注册）

| 闸门 | 条件 | 不通过时 |
|---|---|---|
| G0 复现 | 外部 SOTA 在本机管线干净条件复现论文口径，差距 ≤ 2 pp；否则只能称"架构复现" | 降级为对照，不作为主要竞争基线 |
| G1 退化可观测 | 至少 2 个骨干上，4–5 级退化相对干净 ≥ 5 pp 下降且组 bootstrap CI 不跨零 | 题目动机不成立，先解决评测/强度设定，不进模块 |
| G2 模块准入 | 退化层均值 ≥ +1.0 pp、≥ 2/3 种子为正、干净 ≥ −1.0 pp、其余层 ≥ −2.0 pp | 停止该方向，记录负结果 |
| G3 成本 | 报告参数量、FLOPs、单图延迟；性能提升必须给出"每百分点增益的成本增量" | 只保留同成本下的比较 |

G1 的可行性预警（2026-10-29 实测，`reports/DEPTH_FOG_CHECK.md`）：现有 1–5 级 matched/shifted 雾
在 val 上只让这批组合增强模型掉约 3.5 pp，**达不到 G1 的 5 pp 阈值**——因为这些模型正是用这套雾
训练的。G1 必须改用更强设定（更高 β 档、跨域组合）或改为测**未见过该雾族的外部 SOTA**，
否则"退化显著"在自己的基线模型上无法成立。另：深度条件雾在等均值透射率下没有可测效应
（−0.9 至 +0.5 pp），只能作为真实性升级，不能当作难度手段。

封存规则：FGSC-23 测试集 236 张与 FGSRCS sealed 317 个裁剪**只在方法冻结后各跑一次**；
开发决策只用 val 157 与 FGSRCS development 184。原项目已多次使用 FGSC-23 测试集做诊断，
新课题若要在测试集上报告，必须在论文中披露这一点，或改用 sealed 部分作为主证据。

## 7. 预算

- GPU：单张 RTX 4090 24 GB；原项目已计费 5.16 h / 72 h 上限（`reports/delivery_audit.json`）。
  新路线按"3 个 SOTA 复现 + 3 骨干 × 3 种子 × 1 模块 + 成本测量"估算，训练约 25–35 h，
  评测约 10 h；留 20 h 余量。
- 磁盘：当前 30.5 GB / 50 GB；新退火数据不落盘（按需生成），checkpoint 每运行约 105 MB。
