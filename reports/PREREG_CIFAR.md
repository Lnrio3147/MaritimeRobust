# 预注册:CIFAR-10-C 上复合超出量的复现

写于 CIFAR 训练开始之前(2026-10-31 05:40)。冻结预测,禁止事后改判据。

## 为什么要做这一步

到目前为止所有结论都建立在**一个数据集 + 自写退化族**上:FGSC-23 民用 8 类,
每折 412 张训练图,六个自标定的连续扰动族。这可以支撑"在这个研究里发生了什么",
但支撑不了"复合鲁棒性的度量存在一个问题"这类基准级结论——
审稿人第一句话就是"换一个标准基准还成立吗"。

本预注册把同一套分解搬到**公开标准基准**:CIFAR-10-C,
15 个规范扰动 × 5 个规范严重度(与 Hendrycks 等发布的存档同名同参数),
ResNet-18,标准训练配方。测的是**度量结构**,不是任何一个方法:

    delta = e(a+b) − |E_a ∪ E_b|        (并集基线,误差率空间)
    super = e(a+b) − e(a) − e(b)        (加性基线,误差率空间,即文献常用写法)

两者之差恰为两个单族误差集的交集大小 `|E_a ∩ E_b|`:
`super − delta = |E_a ∩ E_b|`。因此本实验真正测的是**交集有多大**——
也就是"加性基线把多少本来会犯的错重复计了一次"。

## 设计

- 单族:15 族 × 5 严重度 = 75 个条件;复合:105 个无序对 × 5 严重度 = 525 个条件。
  连同 clean 共 601 个条件,每个条件 10000 张测试图。
- 参照模型:ResNet-18,标准 CIFAR 配方(SGD 0.9 momentum、wd 5e-4、cosine、100 ep、
  4 像素 pad-crop、水平翻转),test 精度应在 94–96% 区间;若显著低于 94% 说明配方有问题,
  先修配方再谈结论。
- 逐图正确性(bit-packed)落盘,所有分解可离线重算,不需要再跑 GPU。
- 退化移植保真度单独校验(`cifar_validate.py`):上游 `make_cifar_c.py` **没有设随机种子**,
  存档不可逐位复现;因此判据是"同一模型在存档图与我们重生成的图上精度一致",
  容差 1.0 pp。校验不过,本实验结论作废。

## 冻结预测(阶段 A,观测性)

- **C1** 平均 delta ∈ [0, +8] pp,且多数单元为正(复合误差大于并集)。
  即:并集基线之下仍然是超加性的,但幅度小于海上数据集的 +8.2。
- **C2** mean(super) − mean(delta) = mean(|E_a ∩ E_b|) ≥ 2 pp。
  这条是定义上必然成立的,冻结它是因为**量级**才是结论:文献写法把超出量抬高了多少。
- **C3** Spearman(delta, 复合误差) ≥ 0.3:超出量随复合损坏程度上升。
- **C4** 含天气族(fog/snow/frost)的配对的 delta 比全体中位数高 ≥ 2 pp。
  这对应海上研究中的"破坏性区制"——haze/glare 无论怎么训练都消不掉。
- **C5** s5 平均 delta 比 s1 高 ≥ 1 pp。

## 冻结预测(阶段 B,干预性)

在 CIFAR 上重跑覆盖实验。留出 5 对(`gaussian_noise+fog`、`defocus_blur+contrast`、
`jpeg_compression+snow`、`motion_blur+brightness`、`elastic_transform+pixelate`),跨机制选取。
训练池为剩余 100 对的族均衡嵌套前缀。

- **B1** 留出对上的 delta 随池宽 k 单调下降:k=0(clean)→ k=15 → k=40。
  若 k=40 相对 k=0 的留出对 delta 下降 < 1 pp,覆盖假设在标准基准上**不成立**,
  海上结果必须降级为单数据集结论。
- **B2** 同族单族对照(15 族各一次,不配对)恢复的量显著少于配对臂:
  配对臂 − 单族臂 的留出 delta 差 < −1 pp,即在同样族暴露下配对本身有贡献。
  若两者无差异,论文的主张改为"族覆盖"而不是"对覆盖"。
- **B3** clean 精度损失:任何覆盖臂相对 clean 的 test 精度下降 ≤ 1.5 pp。
  超过则该臂的鲁棒性收益不可与精度代价分离,需要报告精度-鲁棒性权衡而非净收益。

## 判据

| 观察 | 结论 |
|---|---|
| C1–C5 全部通过 | 并集基线下的超加性是标准基准上的普遍现象,海上结果可外推 |
| C1 不过(mean delta ≤ 0) | 海上 +8.2 是小数据集产物,论文降级为方法学案例研究 |
| 保真度校验不过 | 退化移植有误,整套数字作废,先修移植 |
| B1 不过 | 覆盖假设不迁移;论文只保留"两区制"观测结论 |
| B2 不过 | 主张从"对覆盖"降为"族覆盖" |

## 运行偏差记录(2026-10-31,在阶段 A 网格完成之前写)

判据与冻结预测一字不改;以下仅为执行过程中的返工,连同返工原因一并留档。

1. **主干替换。** 首次用 torchvision 原生 stem(7×7 s2 + maxpool,32×32 输入)训练,
   clean test 79.4%(训练集 99.8%)。这是"小图配大感受野"的已知问题,不是本实验的结论。
   改为 CIFAR 式 stem(3×3 s1、无 maxpool)后重训。
2. **轮数。** 100 epoch + cosine 在修好 stem 后停在 clean test 89.6%,低于本预注册
   要求的 94–96% 区间。加长到 200 epoch。
3. **数据增强被冻结(严重,已修复)。** `cifar_train.py` 的 DataLoader 原本
   `persistent_workers=True`。持久化 worker 持有的是 fork 时的 dataset 副本,
   主进程每轮写的 `train_ds.epoch = epoch` 传不进去,于是**每个 epoch 看到的
   裁切/翻转完全相同**——等价于增强只在第一轮生效。症状即上面两条:
   训练精度 ~100%、测试卡在 ~90%。改为 `persistent_workers=False` 后重训。
   前两次的 clean 参考模型(及其尚未完成的网格)作废,不入任何统计。
   影响范围仅 CIFAR:**海上数据的训练脚本没有开 persistent worker**,
   每轮重建 worker 会重新拿到带 epoch 的 dataset,其历史结果不受此缺陷影响。
4. 阶段 A/B 的所有臂(clean、k15、k40、singles)已统一为 200 epoch、同一个 stem、同一个修复后
   的 loader,相互之间只有增强支撑集不同。

**返工后的结果(先记一条,网格尚未跑完)。** 修复 loader 后重训的 clean 参考模型
test 精度 **95.47%**,落在本预注册要求的 94–96% 区间内,engine 与配方由此通过
"C1 之前的健康检查"。这也反证第 3 条:先前卡在 ~90% 不是配方问题,是增强被冻结。
