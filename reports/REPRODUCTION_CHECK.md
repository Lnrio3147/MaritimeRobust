# 归档复现检验

2026-10-30。目的：验证"归档可核查"不是自我宣称——从 `reports/snapshot.json` 出发，把一个已发表的数字重算一遍。

## 被检验的数字

`S2B_SCREENING.md` §1：**R1 多尺度融合，均值 Δ = −1.10 pp**（6 个 (折, 种子) 配对的组合条件准确率差）。

## 步骤

1. 哈希校验：`python scripts/snapshot.py --verify-weights` → 138 个 run 的 `best.pt` 全部与训练时记录的 `checkpoint_sha256` 一致，0 不符。
2. 重跑评估：对 3 折 × 2 种子 × {基线 `none_e40`, `r1_e40`} 共 12 个 run，用 `scripts/explore_eval.py` 重新在 43 个条件上评估，输出写入 `reports/_repro_check/`（不覆盖 `reports/s2b/`）。
3. 逐 run 比对 `combo_mean_accuracy` 与 `clean_mean_accuracy`。

## 结论

- 归档链条完整：快照 → 权重哈希 → 重跑评估 → 已发表数字，全程可复核。
- 复现**逐位精确**，不是"统计上接近"。原因是噪声源全部被固定：退化实例由 `corruption_seed(sample_id, "efmnet", ...)` 决定，权重哈希一致，预处理冻结。
- 因此**任何人拿到本仓库 + 权重，不需要问作者就能复现已发表数字**。

## 局限

- 只检验了 1 个数字（R1 的均值 Δ）与 12 个 run。其余 126 个 run 的权重哈希已校验，但评估未逐个重跑。
- 检验在同一台机器、同一 CUDA 版本下完成；跨硬件/驱动是否仍逐位一致未验证（预期可能因 cuDNN 算法选择出现极小差异）。
